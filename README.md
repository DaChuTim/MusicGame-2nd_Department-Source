# Tamaki₃ 制谱器 v0.1

Godot 4.7.2 实现的《Tamaki₃》谱面编辑器纵向切片。设计依据为：

- `环 GameDesign/新版图文文档_修订版/Tamaki₃ 制谱器设计文档 v2.1（适配玩法 v6.1）.docx`（正文 v2.2）
- `环 GameDesign/新版图文文档_修订版/Tamaki₃ 玩法 v6.1—修订图文版.docx`（正文 v6.2）
- `环 GameDesign/Path设计图/` 的原始 SVG/PNG 视觉参考

首版目标是“能写、能看、能打”：三栏编辑器、u×时间画布、分段边界、Seek、Limit、3D 预览、F5 二值试玩、紧凑代码谱面，以及一套可被文档算例证伪的 `core/` 数学层。

> **合并基线**：本项目是本地 Seek / Limit / 紧凑谱面改动与 GitHub `Axe665/MusicGame-2nd_Department-Source` 的 `d6c82bb` 合并后的版本。

## 运行

```bash
godot --path .
```

或用 Godot 4.7.2 打开 `project.godot` 后按 F6/F5。首次启动会载入 `charts/demo.json`（35 个音符、2 个 BoundaryEvent、2 个 Limit、RingState 关键帧），并自动生成 `audio/demo_click.wav` 的示例音频。

- 空格：播放/暂停；Shift+空格：从头播放；Ctrl+空格：循环
- F5：从播放头试玩；Shift+F5：从头试玩。右上角是「文件 / 编辑 / 视图 / 插入」菜单组加一个黄色「试玩 F5」按钮（原来的「试玩」下拉菜单已合并进这个按钮），点开后底部只有两个选择：**继续游玩**（从播放头）和 **从头开始玩**（从第 0 拍）；试玩中从暂停菜单打开时只剩「完成」
- 开局缓冲：先显示环自绘的加载/READY 层，再 2 秒 3-2-1 倒计时（节拍器滴答）；Esc 取消回编辑器。时间轴自动回退一个预读 + 0.5s，GO 后第一颗音符仍有完整飞入时间，早期的音符不计分
- F6：打开“时间”页（基准 BPM / offset / BPM 列表）
- Esc：结束试玩 / 退出试玩结果 / 停止播放
- 试玩中 `[` / `]`：判定偏移 -5 / +5 ms（±200ms），顶部显示当前 OFF
- 试玩中 F8：AUTO 自动演示开关（也可以勾「试玩设置 → AUTO 自动演示」，或启动加 `--auto`）
- Ctrl+S：保存；Ctrl+Shift+S：另存为；Ctrl+O：打开；Ctrl+N：新建
- Ctrl+Z / Ctrl+Y：撤销 / 重做（200 步）
- 1–7：Tap / Hold / Path / Seek / Anchor / Bell / Limit（Tap 与"大小 Tap"已合并成一张卡，长度在检查器里调）
- B：边界编辑；E：事件；H：HUD；Delete：删除选中
- 右键单击音符 / 红区 / 事件：直接删除；右键按住拖动仍是框选
- 右键拖拽：框选音符；随后左键松开结束选择（结束动作不会放置音符）
- 预览窗：拖动边界控制点；双击分段拆分；Seek 在画布点选时间放置，再按 W/S 选择朝里/朝外
- 文件 →「导入歌曲 / 识别 BPM…」：选音频后自动识别基准 BPM 与 offset，弹窗确认后写入“时间”页
- 画布右上角「从上往下」：关闭后整个写谱区上下翻转（时间向上流动）

## 界面

- 顶部：左上是品牌与当前标签，右上是「文件 / 编辑 / 视图 / 插入」菜单组和一个黄色「试玩 F5」按钮；编辑 → 设置… 打开统一设置窗口（画质 / 界面 / 音频 / 校准；校准向导只在设置里，从试玩设置进去会跳回设置）
- 左 47%：事件轨 + u×时间画布（波形、BPM 线、播放头、连续拍号、小节线、竖线、30° 特殊角度参考线）
- 中 24%：八张音符类型卡 + 音符 / 区域 / 边界 / 事件 / 视图 / 时间 / 谱面七页检查器
- 右侧：可折叠的 3D 预览（SubViewport + Camera3D + 环网格 + 视频背景）；拖左侧把手改宽度，齿轮里收 HUD/调试/收起
- 底部：运输条（播放、时间、进度、BPM、流速、循环、音频弹出）与状态栏

检查器“时间”页是设计文档表 14 中 A 曲目层的时间部分，参考 osu! editor：基准 BPM、offset、固定预读、BPM 点列表和选中点编辑都在同一页；“谱面”页只保留标题/曲师/谱师/难度、音频/视频路径和保存。其余页对应 B–E 层。

## 已实现

- `core/`：TimingMap、BoundaryShape/Segment/Event、ViewState、Region、Note、Chart、ChartIO、Validator、JudgeMath、UndoStack
- 小节线：顶部“小节线”输入每拍等分份数 N（1–64），用于计算吸附交点（网格线已隐藏）；0、负数、小数、非数字提示“数据有误”
- 竖线：顶部“竖线”输入内部竖线数量 N（1–64，默认 11），画布等距显示 N 条竖线并用于计算吸附交点；0、负数、小数、非数字提示“数据有误”
- 音符固定：放置 Tap/Hold/Path/Trace/Anchor/Bell 时，始终吸附到最近的小节线与竖线交点；拖动结束（含批量拖动）会再次吸附；按住 Alt 仍可临时绕过
- 批量剪贴：选中音符后 Ctrl+C 复制、Ctrl+X 剪切，半透明预览跟随鼠标时间；Ctrl+V 粘贴，Ctrl+A 镜像粘贴，粘贴成功后清除预览并选中新音符；单个音符选中时按 A 原地镜像；右侧多选区块显示快捷键提示
- 镜像语义：将音符角度 +180°（超过 360° 自动从 0° 回绕），同时旋转 Bell 的 center_u 与 Path/Trace 平面坐标；不再是 u→1−u 的左右翻转
- 预览方向：默认从上往下；切换为从下往上时，批量复制/剪切的半透明待粘贴音符也同步倒转
- 工具保持：放置 Tap/Hold/Path/Trace/Anchor/Bell 后音符选择块保持当前类型；Path 选完尾点后不再自动切回选择；Esc 取消当前音符类型与待放置 Path
- 点击优先级：音符工具下点击已有音符时优先选中该音符，不叠加新音符；待复制的半透明预览不参与命中
- Hold 放置：第一次左键确定起点，移动鼠标后第二次左键确定终点；终点早于起点时自动交换起止时间，第二次点击不会触发音符选中保护
- Path 选中：命中范围覆盖整条已放置 Path 的可见轨迹（含曲线/视觉折点），擦除段不参与命中，不再只点头尾或起点竖列
- Path 编辑界面重写：隐藏旧的尾半径/尾角度/尾宽度/容差/采样/滑动速度/判定点/擦除/星星颜色等控件，仅保留 **尾部离心 centrifuge**（0.00–1.00，输入框 + 滑块）和 **轨迹轴长 axis**（-2.00–2.00，输入框 + 滑块，-1/L/1 三条可点击锚定线）；axis 为轨迹中点相对头尾直线的有符号距离，0 为直线，负值镜像，中点越出内圆环时自动收紧到最近合法值
- Path 等待：选中 Path 后，在音符属性的“等待拍数”中设置落点到起划的间隔（支持小数拍，默认 0）；等待包含在开始拍到结束拍的总时长内，增加等待会缩短滑动时间。紧凑谱面编码会保存等待时间，兼容没有此字段的旧谱面；此前已保存丢失的等待值需要重新设置或重新导入。
- Path 启动指示：设置页“显示 → Path 启动指示”以及试玩暂停菜单可选择关闭、环形进度、淡蓝收缩圆环。默认环形进度，从头部落点开始，到等待结束填满；收缩圆环则在等待期间由透明渐显，从原头部圆环的 2.5 倍半径收缩，在启动时恰好回到原有大小。起划后 160ms 淡出。预览与试玩共用，选择自动保存；等待为 0 时不显示倒计时，不改变判定容错。旧设置中的渐显、变色、组合模式自动回退到环形进度。
- Path part：在谱面编辑区右键 Path 尾部创建下一段（右键不会触发框选）；原 Path 记为 part0，新段为 part1，依次链接；蓝色尾部/头部表示衔接；各段可分别编辑，预览中只有 part0 头部有星星，星星沿整条链移动，头部圆圈动画缩小一半；整条链的启动指示使用 part0 的等待时间。
- Path 兼容：旧版 demo 已改写为 centrifuge/axis/trace 新字段；读取其他旧谱面时同样在加载阶段迁移，显式旧轨迹也会补全新字段
- 数值输入保护：焦点在任意 SpinBox / 数值输入框时，数字键 1–7 不再触发音符工具切换，输入框正常接收数字
- 框选与多选：框内或与框相交的音符（含 Hold/Trace 体、Path 轨迹、音符圆头与头尾）都会选中；长按 Ctrl 左键单击音符切换该音符选中状态，并阻止放置操作，可连续加选/取消
- 框选流程：右键确定起始时间，滚轮上下移动编辑区不会改变该起点；左键确定结束时间，起点晚于终点时自动交换
- 纵向拉伸：Ctrl+滚轮按 0.1 调节纵向拉伸；值限制在 0–10，达到边界后继续滚动不会继续放大/缩小
- 界面精简：隐藏分音网格、右列分音选择器、顶栏 SNAP、检查器“分音”；重新显示小节线、竖线与 30° 特殊角度参考线，保留连续拍号与 BPM 线
- 纵向拉伸：顶部“纵向拉伸”支持 0–10 的整数/小数输入与滑条；每 bar 距离变为原来的 `1 + n×0.5` 倍，小节线等比拉伸，音符头/图标尺寸不变
- 音频：支持 WAV/OGG/MP3/FLAC（FLAC 经 ffmpeg 解码缓存）；应用条件为 BPM 检测成功、offset 在单拍范围内、播放流时长与解码音频时长一致
- 新建谱面：选择音频后自动测量 BPM 与 offset；BPM 最多保留 3 位小数，只有 1 位小数时四舍五入取整；offset 保留 3 位小数
- 打击音效：试玩命中与编辑器播放共用 `HitSfx` 音效池（don/kat/铃/Path 尾/擦带），10 路播放器轮转 + 轻微随机音高；资源在 `audio/sfx/`
- 编辑器播放打击音：运输条「音频」弹出里的“打击音”开关，播放时按音符时间触发 Tap、Hold 头/尾、Path 头/尾、Anchor、Bell、Trace；不影响试玩
- 光标：Estella 风格白色环 + 青色内环 + 旋转弧 + 深色描边 + 拖尾；预览内始终隐藏系统光标并绘制自定义光标
- 流速：运输条“流速”0.05×–3.0×，步进 0.01，只缩放预读速度（`pre_read_ms ÷ flow_scale`），不改判定窗口；试玩沿用当前设置
- 倍速：试玩设置（F5，或暂停菜单 →「试玩设置」）里的“倍速”0.5×–2.0×（步进 0.05），试玩和编辑器试听都按这个速度走；**声音不变调**——用 ffmpeg `atempo` 预生成该倍速的音频并缓存（音质最好；每个新倍速首次等约 2–5 秒，之后秒开），BGA 视频跟速，READY 倒计时仍按真实 2 秒；没有 ffmpeg 时回退成变调并在日志/提示里说明；局中修改在重开本局后生效；倍速本身只对本次运行有效
- 星速：运输条“星速”0.75×–1.5×，同时缩放滑条引导星移动速度与所需跟随距离
- 视角：视图页“正对镜头（忽略倾斜）”默认开启，试玩时环面始终正对相机；需要作者镜头时可关闭
- 打击音：新增 Hold / Path / Anchor 分层音色（合成 WAV，瞬态 + 音体 + 短尾）；Trace 离开轨迹超过 250ms 会重置累计距离（FRAY）
- 环：正对镜头 + 鼠标倾斜/视差；所有 note 厚度与星头按环半径等比缩放，Tap/Path/Trace 统一 32px 外圈、13px 主色
- Simai：可直接选解压后的 `maidata.txt` 或文件夹，音频直接使用同目录 `track.*`；zip 导入仍解包并转 OGG；同刻冲突只保留最宽一侧
- 音量：运输条「音频」弹出里的“音乐”“音效”两个滑杆，分别控制 `Music` / `SFX` 总线；编辑器播放、试玩、打击音共用总线设置
- 游玩范围：所有 note 以**八角舞台安全矩形**为准；手绘 Trace 在落点时夹到安全区，环上 note 保持在环内
- 接近表现：所有音符（Tap / Hold / Path / Trace / Anchor / Bell）都从圆心飞向判定环并随预读放大，轨迹和星尾一起长出，不再原地出现；Hold 完成后 0.24 拍渐隐
- 长度体系：l = 旧版 Tap 与判定环重合时的条带长度（即 `note.width`）。新版普通 Tap 与 Hold 头都是 **0.5 l**，且"看到多长 = 能打多长"（绘制与判定共用 `Note.arc_width()`）；**Tap 的长度**直接在检查器「长度倍率 ×l」调到 **0.00–1.50 l**（两位小数），实际弧宽 = 基础宽度 × 长度倍率；改离 0.50 就自动变成"大小 Tap"，「恢复普通 Tap（0.50 l）」按钮可还原，0 长度仍保留一个点标记；Tap / Hold 在环心出现时只有 **1/6 l**，飞近判定环时长到 1 l
- Path 视觉尺寸 ×2（`PATH_SIZE_SCALE`）：轨迹笔画、V 形箭头、星头、尾环、进度球全部放大，轨迹几何与判定不变；Trace 使用重做后的门框/游标绘制
- Hold 叠放：同角度连续 Hold 按时间做深度淡化（越晚越淡，下限 65%），身体与头/尾分两遍画，所有头都压在身体上层；最近要按的一颗额外带一层头带柔光。判定角度与时间不变
- Hold 外观：头部与 Tap 用同一条"长度条"（`_draw_length_band`），只是主体色换成黄色，缩放节奏与 Tap 完全一致（环心 1/6 l → 判定环 1 l）；身体从**圆心**画到 **1.44R**（旧版 0.28R→1R 的 0.72R 的 2 倍，外端越过判定环 0.44R），飞入时同样跟着 `grow` 长出来
- osu!std 落道：照 Sentakki 的 8 道 45°（`_std_closest_lane` / `_std_lane_u`），流向用它的中点法（`_std_stream_direction`：同向保持、共线归零、否则取角差符号），大跳按两端道差（`_std_jump_offset`），间隔超过 1 拍重新回绝对位置
- 星星颜色：默认使用全局星色（舞萌蓝）；有任意两条 Path 在**时间 + 盘面轨迹**上重叠时，按同色系逐级压明度区分。旧版自定义 RGB 数据（`"rgb"`）保留兼容；新 Path 界面已隐藏该入口
- osu!std 滑条：照 Sentakki 的**程序化段链**（`core/sentakki_slide.gd`）——不跟随 osu 控制点，而是从 `Straight / Circle / V / U / Cup / Thunder / Fan` × 8 道 × 镜像的合法段表里，按剩余时长反复挑段（`min_ms × (1 + 1/velocity) < 剩余`），连续同向圆弧不合法；wait 从 1 拍开始减半，低于 0.5 拍退回 Hold；轨迹按弧长匀速采样
- 舞萌转谱（`ConvertOptimizer`）：同刻只留一颗（星星 > Hold > Tap > Bell，同类型看谁更顺）；星星时间重叠时前一条能缩短就缩短，缩不了后一条只留星头降 Tap；缩短/截断后把后一颗头吸到前一条尾，形成一笔画；每条星星按 3600px/s 的鼠标上限压短轨迹；严格 A-B-A-B 两位置交互（≥5 颗、平均快过 2200px/s）整段锁到一对 45° 位置，连 45° 都追不上的（253px ÷ 间隔 > 2200px/s）整段收到第一颗角度、光标不用来回甩；≤45° 邻键的快速 Tap 来回（≥3 颗，允许轻微漂移，单向扫台阶不算）整段收到第一颗角度形成「叠键」，其余超过 45° 且快过 2200px/s 的折返逐颗压成 45°；压角/Hold 降级后再补一遍只叠不改别的；Bell 撞上 100ms 内的 Tap/Hold 时吸到同一角度（单光标不可能同时站两处）；快速扫键段（≥3 颗连续 Tap、间隔 ≤45ms、每颗至少移 10°、总跨度 ≥45°）一对一转成 Bell，用鼠标沿路线扫过去收；同角度连打不转，但间隔 ≤60ms、≥3 颗的同角度连爆会隔一颗删一颗（19 颗/秒 → ~9.5 颗/秒，保持 Tap）；星星期间只留落在星轨 0.30R 内的 Tap/Hold/Bell；Hold 尾巴撞到下一颗按键时缩短，不足半拍降 Tap
- 转谱底线（`ConvertOptimizer`）：时长 < 160ms 或头尾弦长 < 0.6R 的滑条直接降级成 Hold/Tap（这样的 Path 玩家读不出"要滑"；240BPM 的 1/8 拍滑条就落在这条线下，120–180BPM 的常规滑条不受影响）；星星期间压不在轨上的 Bell 直接删掉——一个鼠标没法同时跟滑条又去接铃铛
- Path 判定（试玩）：轨迹按弧长（约 0.85R）、明显拐点、自交切成**有序判定组**；走廊半径通常为 0.25R（常见视口约 67px，短轨迹缩至轨迹长度的 18%），主要拐角放宽至 0.34R。光标按顺序经过组即可消组，允许向前跳 1 组；3 组以内的短滑条禁止跳组。星头命中自动免除第一组。中段无需持续按键，头尾独立计分；身体清完后**进入尾区即结算**；参考点是**星星进入尾区**（不是 Slide 终点），早到窗口按尾区停留/4 扩展（上限 22 帧），晚到仍按终点计。档位：PERFECT ±150ms / GREAT ±220ms / GOOD ±350ms，早到不掉 Miss，晚到 >350ms 才 Miss；结束时刻只剩最后 1 组给 GOOD

- 开局缓冲：时间轴允许退到负拍（预读 + 0.5s）。osu 谱的第一颗常在音频 2–5 秒处，以前被夹在 0 以上、GO 后第一颗直接贴脸；现在直接吃音频自带的前奏。若第一颗就贴着音频 0 秒，则 GO 后最多 1.5 秒无声等音符飞入，音频延后起播
- osu!std 混合层导入：circle → 环上 Tap（连续 u）；slider → 环内平面 Path（星头按键 + 沿轨迹移动，尾部进入尾区后按判定偏移结算）；lazy/短 → Hold；重复滑条按 Sentakki 段链转成单向 Path；滑条带 Sentakki 式 wait 阶段。转换后只做两件鼠标保护：同刻多押只留一颗（星星 > Hold > Tap），以及星的尾判与后一颗头同拍时把后一颗头吸到前一条尾
- 连续角度：流内按 Sentakki 式 45° 步进，jump 用两端道差，间隔超过 1 拍回绝对位置
- 可变 Tap 宽度：按相邻角度/时间补偿（45–75°），密集段更容易跟，jump 略窄
- 负拍前奏：最早 note 自动平移到 beat 0，并调整 offset；F5 从头不会漏前奏
- 试玩延迟：`audio/driver/output_latency=10`；顶部 `OFF` 与 `[` / `]` 可手动校准音频/输入综合延迟，Path 头尾改为窗口内可命中而不是窗口一开始就判 Miss
- 存档：JSON 主格式、原子写、`.bak.1..5`、60 秒/20 条命令自动保存、`user://autosave.json` 手动恢复
- 演示：32 音符示例谱、示例点击轨、3D 预览、五角星 Path 示例、试玩事件日志

## 格式互通

- **转谱窗口**：导入 `.osz` / `maidata.txt`，或者从「在线舞萌谱面」下载完成，都会先把来源里的**所有难度都转好并存成一个套组文件**（`user://sets/<曲名> [导入].set.json`），再**另开一个窗口**（`--open-set=<set.json> --child-window`）专门编辑它；父窗口的谱面原样不动。新窗口和普通编辑器一样，只是顶部左侧多一个「难度」下拉框，可以在套组里的所有难度之间直接切换（`<曲名> · <难度>` 会显示在标题栏）。在线谱面下载后不再在浏览器里选难度，统一在新窗口切。自动保存写到 `user://autosave_import.json`，不碰主窗口的 `autosave.json`。
- **难度套组 `.set.json`**：一个文件装一首歌的所有难度（`{"format":"tamaki3-set","difficulties":[{"name","chart"}]}`）；`ChartIO.load_set/save_set` 读写，`文件 → 打开` 会自动识别，Ctrl+S 存回整个套组；`文件 → 新增难度（复制当前）` 加一份，`文件 → 另存为` 则把当前难度单独存成普通 `.json`。
- **在线舞萌谱面**：卡片列表（封面 / 曲名 / 艺术家 / 难度色块 / 收藏 / 详情），adxdls 与 majdata 用搜索栏旁的分段按钮切换；majdata 接口固定 30 条/页，底部可上一页 / 下一页 / 输入页码；点卡片任意位置看详情（谱师、上传者、全部难度、BGA 状态与大小），下载时询问「带 BGA / 不带 BGA」，没有 BGA 的谱面直接下非 BGA；BGA 失败只提示，不阻断谱面导入。adxdls 首次打开按当前页懒加载封面（bg.webp）和难度等级（maidata），落盘到 `user://chart_cache/` 后再次打开秒开；收藏写入 `user://chart_favorites.json`，「只看收藏」只筛当前源。osu! 仍是独立窗口。
- **在线 osu! 谱面**：`文件 → 在线 osu! 谱面…` 独立窗口，**打开即显示「最新上架」**（镜像空搜索返回 ranked 时间倒序；第一次打开且没有列表时才拉，不在编辑器启动时打网络；清空搜索框回到第 1 页），交互和舞萌浏览器对齐——卡片式列表（封面 / 曲名 / 艺术家 / 前 4 个“星数 + 难度名”药丸，超过 4 个时末尾“+N ▾”在卡片内展开），**点卡片进详情页**（封面、原文曲名、谱师/来源/tags、全部难度星数、BPM/时长/游玩/收藏/状态、包体大小）；详情页按谱面是否带视频给 **「带视频下载 / 不带视频下载」**（实测镜像的“去视频包”和完整包是同一个文件，「不带」= 导入后删除视频文件、不绑定 BGA）；**30 条/页**，底部是「上一页 / 页码 / 下一页」（搜索镜像不给总数，所以只显示第 N 页，翻回已加载页不再请求）。搜索走 `osu.direct` 镜像（只列带 osu!std 难度的谱面包），封面来自 `assets.ppy.sh` 并缓存到 `user://osu_covers/`；下载走 sayobot（失败退回 `osu.direct`），下载中显示已下/总量/速度，拿到 `.osz` 后与本地导入走完全相同的转谱管线。点卡片右侧 ☆ 收藏谱面包（写进 `settings.json`）；漏斗按钮展开一行 **类型 / 语言 / 标签 / 只看收藏** 过滤：类型与语言用的就是 osu! 官网的枚举（`genre_id` / `language_id`），标签按 `tags` + 曲名 + 艺术家做 token 匹配（空格或逗号分隔，token 之间 AND，忽略大小写），因为 osu.direct 的搜索接口会忽略 `genre` / `language` 参数，所以每页 30 条候选在本地过滤；封面同时最多 3 个请求、按需倒入，已经下过的存在 `user://osu_covers/<id>.jpg`；搜索框也接受 `beatmapsets/<id>`、`beatmaps/<id>`、`/s/<id>` 链接或纯数字 ID（直接打开详情页；谱面 ID 会经 `osu.ppy.sh/osu/<id>` 的 `BeatmapSetID` 解析成谱面包，不需要 OAuth）。osu 包里的 BGA 是 `.m4v`，已加入直解表，不再转码。
- **osu! storyboard**：导入 `.osz` 时如果包里有 `.osb`（或 `.osu` 内联的 `[Events]` Sprite/Animation），会一起解析——图层（Background / Foreground / Overlay）、9 种原点、`F/M/MX/MY/S/V/R/C/P` 命令、缓动 0–35、`L` 循环（解析时展开成绝对时间段）、`Animation` 帧序列都支持；素材按引用名解包到 `user://imports/<曲名>_<hash>/sb/`，路径记在 `chart.metadata.storyboard`。预览/试玩里 Background 画在 3D 判定环**下面**、Foreground/Overlay 画在环上面，时间轴用 `chart.ms - offset`（和视频同一套基准）；视图菜单和试玩设置里都能开关「故事板」（写进 `settings.json`）；storyboard 的 Background 层里出现谱面背景图时，静态背景层会自动隐藏（对照 lazer 的 `ReplacesBackground`）。编辑器右侧的小预览会把整块 storyboard **等比缩到装得下**（`storyboard_fit`），试玩仍按高度铺满。

坐标按 osu 的 `ToScreenSpace` 规则映射：**按高度缩放、场中心对齐屏幕中心**（宽屏只是左右多露出来），不做 cover 拉伸，所以 1920x540 这类横条只占 75% 高度、不会糊满全屏；谱面背景图始终垫在 storyboard 下面（和 stable 一致）。`P,A` 加色元素走单独的 `BLEND_MODE_ADD` 图层（背景/前景各一层），alpha 压到 35% 防止几百张全屏图叠加刷白。

**背景暗度**：试玩设置里新增「背景暗度」（**0–70%**，和 osu 的 Background dim 一样），只压背景与故事板，不压判定环和音符；数值会存进设置，编辑器和试玩都生效。

**故事板编辑器**：`插入 → 故事板编辑器…`（原来在「文件 → 导入」里，已挪到「插入」）。

**多标签启动**：`--open-tabs=a.set.json|b.json` 一次开多个标签页（`.set.json` 走套组，其余按普通谱面 JSON 打开）；不带参数时读设置里的 `startup_tabs`（默认：`res://charts/demo.json` 示例谱 + `Shoujo A [参考].set.json`）。切标签时会调用 `Preview3D.invalidate_storyboard()` 让故事板层重新解析，避免沿用上一个标签的画面。可新建/复制/删除对象（图层、原点、位置可改），给对象加命令（`F/M/MX/MY/S/V/R/C/P,A`，含缓动 0–35 与起止时间），编辑器带一条**多对象时间轴**：每行一个对象（按图层排序，左侧有名字栏），彩色条是它的命令；刻度区点/拖跳预览，拖条中间整条平移、拖边缘改起点/终点，点条选对象；滚轮上下滚、Ctrl+滚轮缩放时间轴。带**节拍吸附**（关 / 1/1 / 1/2 / 1/4 / 1/8 拍，用谱面 BPM 表换算）和**撤销/重做**（快照存 .osb 文本，最多 50 步），改动实时反映到右侧预览（不用先存盘）。「保存并应用」写回 `user://storyboards/edit_<hash>/storyboard.osb`，导入目录不会被改动（首次保存时自动把素材复制到编辑目录）；也支持「导出 .osb…」。

素材每帧预取 6 张、采样按 30Hz（60fps 下不重复求值 700+ 对象）、按 500ms 分桶只遍历当前窗口的对象、命令窗口外走首尾值缓存。谱师可以直接照搬 osu! 的 storyboard 工作流：用 osu! 的编辑器做完导出 `.osb` + 图片，再 `文件 → 导入 → 故事板 (.osb)…` 挂到当前谱面（图片按文件名拍平复制到 `user://storyboards/`）。实现移植自 ppy/osu 的 `LegacyStoryboardDecoder` 与 `osu-framework` 的 `DefaultEasingFunction`。
- **导入 `.osz`**：支持 osu!std 与 osu!taiko；circle → Tap、slider → Slide Trace/Hold、drumroll → Hold；spinner 跳过；多难度包会弹窗选择 `.osu`；导入报告列出保留/丢弃原因。

- **导出 `.lbp` v2**：按设计文档第 7 章输出 `[General] / [Video] / [Metadata] / [TimingPoints] / [BoundaryShapes] / [BoundaryEvents] / [ViewStates] / [Regions] / [Notes] / [Editor]`，保留 Path 五角星、Trace 二维点、Bell、Anchor 配对和颜色/锁定选项。
- 导入时会把 `.osz` 内的音频、背景、视频解包到 `user://imports/`；音频仍可用 ffmpeg 转码。
- Simai 的 p/q、pp/qq、s/z、V、w 现在按形状精确生成（不再近似成圆弧）；自交的 Cup/闪电保留原形状，只有超过鼠标速度上限时才压短轨迹；中心 Touch 和 Touch Hold 会导入成圆心/中圈 Bell，Touch Hold 忽略时长。

## 结构

```text
core/      引擎无关的谱面模型、时间/边界数学、校验、JSON
charter/   编辑器 UI、3D 预览、画布、检查器、试玩
assets/    内置 Noto Sans CJK SC / Noto Sans Mono 字体
audio/     示例点击轨（脚本生成，18s）与试玩打击音（CC0）
```

`core/` 不依赖窗口/音频/皮肤，后续 game 项目可直接复用；编辑器、预览、试玩共用同一套 `C(u,t)`、`P(u,q,t)`、最近点求值与校验器。

## 媒体格式

| 类型 | 直接支持 | 自动转码（需要 ffmpeg） |
|---|---|---|
| 音频 | WAV / OGG / MP3 | FLAC / M4A / AAC / OPUS / WebM / MP4 |
| 视频 | Ogg Theora（.ogv）+ MP4 / M4V / WebM / MOV / MKV / AVI（gdffmpeg 直解） | 缺解码库时兜底转 OGG Theora |

BGA 走 gdffmpeg 直解（见下一条）；音频仍按下面的表转码，结果缓存到 `user://media/`，按源路径 + 文件 mtime + 大小哈希命名；替换同路径源文件会自动重转。谱面仍保存原始路径。视频用于环后背景层，默认 35% 不透明度（再乘全局「背景明暗」），`videoOffset` 独立于音频。导入入口：`文件 → 导入视频…` 或检查器「视图/设置 → 视频 → 选择视频…」。

BGA 默认**直接解码、不转码**：`addons/ffmpeg` 里带了 [EIRTeam.FFmpeg](https://github.com/EIRTeam/EIRTeam.FFmpeg)（MIT，GDExtension + libav），仓库里已提交 Windows / Linux x86_64 的库和 FFmpeg 运行时，克隆下来就能用。`.ogv` 仍走引擎自带的 Theora，mp4 / webm / mov / mkv / avi 直接交给 gdffmpeg 解码，**导入带 BGA 的谱面不再冻结、也不产生转码缓存**。检测到 BGA 时不再叠加谱面的静图背景。

兜底：如果平台没有对应二进制（macOS / Android / arm64），或解码库加载失败，会自动退回原来的 ffmpeg 后台转码（540p30、带进度、写 `user://media`），`.ogv` 之外仍能播。要补平台：把上游 release 里对应目录放进 `addons/ffmpeg/`，在 `ffmpeg.gdextension` 的 `[libraries]` / `[dependencies]` 补两行即可。设置 →「转码 / 变速缓存」可以看占用并一键清理。

## 已知限制

- 非原生音频/视频格式依赖 `ffmpeg` 在 PATH 中；**变速不变调的 `atempo` 预生成也需要 ffmpeg**，没有时倍速会回退成变调并提示。原生 WAV/OGG/MP3 与 OGV 在没有 ffmpeg 时仍可用。转码 / 变速缓存位于 `user://media/`，谱面保存的是原始路径，便于重新链接。
- 自动识别 BPM/offset 需要能拿到 PCM：WAV 直接解析，其余格式（含 mp3/ogg）要用 ffmpeg 解成 11 kHz 单声道并缓存到 `user://analysis/`；可在导入弹窗里指定 ffmpeg 路径（存于 `user://editor.cfg`）。识别结果是初值，半速/倍速、弱起前奏仍要人工确认。
- 分音 UI 已隐藏，`GridDivisions` 仅保留内部兼容/其他吸附；音符固定使用当前小节线与竖线交点；拍号分母仍固定 4。
- 预览默认开启 3D 环网格；环/舞台/刻度是 GPU 网格，音符与 HUD 仍是 2D 叠加（按本轮取舍，保证编辑精度）。旧机器或集显可在“视图”页关闭 3D 环网格回退到投影环线。
- 视频是背景层，音频仍是唯一判定时钟。
- 边界编辑器是“分段参数 + 控制点 + 预设”，按本次要求只允许**简单凸轮廓**；凹口、星形、折返、自交、局部半径过激都会被校验拒绝。`b` 插值按平滑曲线处理，语法保留。
- 局部 BoundaryEvent 仍可用，但若过渡中产生凹口/自交也会被拒绝；首版示例使用整环事件。
- 试玩提供分档判定、事件日志和调试准确率/评级，尚未采用正式评分公式。Path 中段按有序判定组 + 容差扫描确认滑动，头尾独立计分；头部 MISS 后仍可从轨迹起点完成滑动以获得尾判。
- osu!std 的 slider 按 Sentakki 段库转成环内平面 Path（星头按键 + 沿轨迹，尾部进入尾区后判定）或 Hold（lazy/短）；circle 仍是环上 Tap，角度按 8 道 45° 的流/大跳推进。Path 头尾一起出现，尾部有独立 Hit/Miss。
- 试玩时钟不预测起播：音频真的出声后（`playback > 0`）才用**实际播放位置**锚定，误差不随平台和单次采样变化（`get_time_to_next_mix()` 会变负，`get_output_latency()` 在 PipeWire 上实测 29–58ms 抖动）。驱动延迟只用于把「混音位置」换算成「听到的位置」，起播后 250ms 内取中位数后**冻结**，之后不再追噪声；漂移校正带 4ms 死区，只处理真实卡顿。驱动报 0 的驱动自动退化成混音位置时钟。PC 实测缓冲设置直接决定总延迟（`driver/output_latency` 10 → 39ms，3 → 12ms），所以项目里设成 3ms + 48000Hz；如果某台机器听到爆音/咔哒，在设置 → 音频缓冲里换「标准 10ms」（写 override.cfg，重启生效）。试玩设置里的「输出延迟」：0 = 用驱动报告值，>0 = 强制覆盖；校准只改「判定偏移」，不改输出延迟。
- 命中窗口固定 40ms，尚未做 Perfect/Great/Good 分级；评分规则仍等文档冻结。
- 拍号分母固定 4；3/8、6/8 需要后续 BeatUnit 扩展。
- 示例音频是节拍点击轨，不是正式曲目；可以用“谱面”页替换音频路径。
- `.osz` 多难度包会弹出选择框；如果包内难度没有音频，仍可导入但预览无声。
- taiko 的 don/kat 会合并为 Tap，用宽度（58/76/90）区分 don/kat/大音符，不保留原颜色语义；车道按两车道就近分配，密集段堆叠。这是当前约定的导入映射。
- 打击音是 Freesound CC0 素材（Wood block hit / wood block / ShiningRinging / Fast swipe / Thin bell ding），来源与授权见 `audio/sfx/ATTRIBUTION.md`。
- 流速是编辑器/试玩会话选项，不写入谱面；谱面仍只保存固定预读 `pre_read_ms`。
- 音量滑杆目前是会话级，不写入谱面/配置文件；重启后回到 100%。
- osu!std 混合层是“可玩性重解释”，不是原谱 1:1 还原；Tap 角度经过 Sentakki 的流向/大跳推进，slider 的轨迹由 Sentakki 合法段链按剩余时长生成，不是原图逐点复刻。

## 打击音效与替换

编辑器播放和 F5 试玩共用 `charter/hit_sfx.gd`，音效文件都在 `audio/sfx/`：

| 文件 | 用途 |
|---|---|
| `tap_don.ogg` | 普通 Tap / don、Hold 头部 |
| `tap_kat.wav` | kat Tap（当前以音符宽度 70° ≤ width < 85° 区分） |
| `hold_end.ogg` | Hold 完成（头尾均不再额外调整音高） |
| `path.wav` | Path 头部、滑动型 Trace 起点 |
| `path_tail.wav` | Path 终点 |
| `trace.wav` | Trace 完成；编辑器预听在起点触发 |
| `anchor.wav` | Anchor 命中 |
| `bell.ogg` | 金键命中 |
| `slide.wav` | 星星开始沿轨迹移动（`beat + wait`）时的“起划”提示音 |

替换时可使用 WAV（建议 44.1 kHz、16 位 PCM）或 OGG Vorbis，短音效建议去掉起始静音。覆盖对应同名文件，然后回到 Godot 等待重新导入并重新运行游戏。保留 `.import` 文件，它记录导入设置；不要修改 `.godot/imported/` 中的缓存。如果使用新文件名或格式，修改 `HitSfx.PATHS` 中对应路径。

`HitSfx.KIND_DB` 控制各类音效的音量（dB）；`STYLE_PITCH` / `STYLE_DB` 控制“原声、清脆、厚重”的音高与音量，它们共用这 8 个文件。编辑器运输条的“音效”滑杆控制共用 SFX 总线，“打击音”复选框只控制编辑器预听；外观设置中的“打击音效 → 静音”同时影响编辑器和试玩，恢复为“原声”即可解除。

音效回归测试：`godot --headless --path . --script tests/sfx_playback.gd`。覆盖 8 种音效的总线输出、舞萌导入谱和自制谱的编辑器/试玩触发、卡帧后补发、跳转不补播和试玩静音切换；不验证扬声器或耳机的实际输出。

Path 判定回归测试：`godot --headless --path . --script tests/path_judgement.gd`。覆盖快速经过、直接碰尾、弯折/回环/折返、等待段、输入中断、重叠轨迹、容差跳组、短滑条保护、AUTO、重开和轨迹消除。

Path 判定采用“有序判定组 + 容差扫描”：轨迹按弧长（约 0.85R）、明显拐点和自交切分为若干组；光标按顺序经过组即可消组，允许向前跳过 1 组（跳区），但 3 组以内的短滑条禁止跳组；星头命中自动免除第一组（A 区免判）。身体完成后进入尾区即完成，档位只看尾判时机；结束时刻还剩 1 组没消记 GOOD，差更多才 MISS。判定组在环的局部坐标里生成，环变形、旋转、倾斜、缩放和任意平面滑条都适用；自交/折返会按前进方向过滤，避免走到另一支。

本分支的 Path 输入诊断默认随试玩开启，`F9` 可关闭/重新开启。日志在 Godot 用户数据目录的 `logs/path_input_*.jsonl`（Windows 默认 `%APPDATA%\Godot\app_userdata\Tamaki₃ 制谱器\logs`），记录谱面、判定偏移、判定组几何、当前光标/下一组、距离/容差/剩余组、输入批次及完成状态；活动 Path 每 200ms 采样一次，约 4 MiB 后停止记录。退出、重试或正常结束会关闭日志；可在问题发生后退出试玩，将最新日志用于分析。

试玩按 `F10` 或在暂停菜单开启“显示 Path 判定区域”，可显示真实判定组：绿色为已消组、蓝色为未消组、橙圈为下一组、红圈为 MISS 后未通过的区域、白圈为尾区，文字显示当前组数、容差和剩余组数。显示层读取实际判定模型，默认关闭。
